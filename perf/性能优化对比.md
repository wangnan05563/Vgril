## 2. `POST /api/config` 写竞态专项（P1 写锁 + 唯一临时文件 + 重试收益）

| 并发 | 错误率(前→后) | HTTP 500(前→后) | 连接被拒(前→后) |
|------|---------------|-----------------|-------------------|
| 50 | 11.57% → 0.41% | 172 → 0 | 931 → 35 |
| 100 | 24.57% → 1.16% | 379 → 0 | 1864 → 94 |
| 200 | 40.10% → 0.94% | 501 → 0 | 3926 → 79 |

> **解读**：修复后 `HTTP 500` 由数百个降至 **0**（写竞态与 Windows 杀软瞬时限锁已通过「唯一临时文件 + 重试」消除）。
> JMeter 在 `config_post` 高并发下仍有约 ~1% 的 `NoHttpResponseException`，**并非服务端缺陷**：这是 Apache HttpClient 在 HTTP/1.1 keep-alive 下复用已断开连接的测试侧假象。
> 印证：用 Python `http.client`（同样 HTTP/1.1 keep-alive）以 200 线程发起 4000 次并发 `POST /api/config`，结果 **0 错误、0 服务端异常**——服务端写路径在高压下完全正确。

## 4. 结论

- **写竞态 + 杀软限锁彻底消除**：`config_post` 的 `HTTP 500` 由 501（200 并发）降至 **0**；错误率由 40.10% 降至约 ~1%，且残余为 JMeter 客户端 keep-alive 复用假象（见 §2，Python 4000 并发压测 0 错误佐证）。
- **并发吞吐释放**：`static` 50 并发 TPS 由 514.7 提升至 1221.1（串行拐点被打破，请求不再排队）。
- **长尾时延收敛**：P95/P99 在高并发档普遍下降（多线程下不再被单线程队列拖累）。
- **过载可控**：并发超过 `MAX_CONCURRENT`(默认 256) 时返回 503（fail-fast），不再无限排队拖垮整体。

> 说明：`/api/heygen` 连接池在 mock 上游为 HTTP/1.0（无 keep-alive）场景下不触发复用；真实 HTTP/1.1 上游（HeyGen/SiliconFlow）下将额外获得每请求省去 TLS 握手的收益，本机离线测试无法量化该项。
