## 1. 产品现状概述

### 1.1 一句话定位
本地优先、可离线运行的**单文件网页数字人伴侣**：三栏布局（导航 / 傲娇人设聊天 / 数字人形象 + 语音），默认走本地人设引擎，可接入大模型与数字人视频，并内置字幕导出 + 录屏烧录工作流。

### 1.2 当前能力清单
- **人设引擎**：傲娇、爱吃醋、会委屈的本地状态机（关键词 + 情绪），离线可用。
- **三栏交互**：左导航（聊天 / 记忆库 / 设置 / 数字人状态）、中聊天区、右小雅人像（CSS 呼吸 / 口型脉冲动画，可切数字人视频）、底部圆形语音按钮。
- **语音**：TTS（浏览器 SpeechSynthesis，可调语速 / 音调）、STT（Web Speech 中文识别）。
- **记忆**：对话存浏览器 `localStorage`，可查看 / 清空。
- **内容创作**：实时字幕 + 导出 `.vtt` / `.srt`，`record_burn.ps1` 录屏烧录字幕。
- **设置**：4 套皮肤主题、TTS 滑块、BGM 上传、数字人高级配置。
- **接入层**：OpenAI / DeepSeek 兼容大模型（失败回退本地）；数字人反向代理（HeyGen、腾讯智影），密钥留服务端做签名规避 CORS 与明文暴露。
- **分发**：PyInstaller 打包 `CodexQQSkin.exe`，零依赖双击运行。

### 1.3 技术架构要点
- 前端单文件 `index.html` + 底图 `xiaoya.png`；后端 `server.py` 静态托管 + 数字人反向代理 / 腾讯云 TC3 签名。
- 本地优先、数据不出本机是核心差异化（区别于几乎所有云端竞品）。

### 1.4 数据流向与隐私边界（P0 修订 v1.1）
为消除"数据不出本机"绝对化表述与实现之间的张力，明确两种运行模式：
- **本地模式（默认）**：人设引擎、记忆、字幕、语音兜底全本地闭环，**零出站**，真·不出本机。
- **增强模式（显式开启）**：接入大模型 / 数字人视频 / 神经语音时，对话文本/语音按需出境第三方，**须用户显式授权、可一键退回本地、记忆不随出境携带**。
- 对外隐私承诺修订为：「本地优先 · 默认不上云 · 增强明示出境可关」。任何出境均最小化传输（仅当前轮必要文本，不含历史记忆 / 情绪 / 危机日志）。
- 详见《修订_安全与一致性_P0.md》§1（数据流向矩阵）。

### 2.2 监管与安全红线（决定产品生死，优先级最高）

> **重大变更（2026-08 检索确认）**：国家网信办等五部门《**人工智能拟人化互动服务管理暂行办法**》已于 **2026-04-10 公布（令第21号）、2026-07-15 正式施行**——是全球首部专项规章，此前文档中的"征求意见稿（2025-12）/ 正式稿待复核"表述**已全部失效**，本条合规项须按正式稿执行。

### 2.5 行业共性痛点（= 小雅的机会窗口）
1. **记忆浅**：多数 App 跨会话即忘，长期关系感弱。
2. **同质化**：玩法高度雷同，体验趋同，留存难。
3. **语音机械**：TTS 依赖系统语音包，延迟高、情感单一。
4. **合规风险**：未成年人保护、AI 标识、情感危机干预普遍缺失或后置。
5. **留存差**：3 日留存 <20%，5~7 天流失。
6. **变现难**：单一订阅水土不服，国内付费意愿低。
7. **隐私**：云端训练用户对话成默认，泄露事件频发。

## 3. 现状差距分析（Gap / SWOT）

### 3.1 优势（Strengths）
- **本地优先 + 可离线**：数据不出本机、不参与训练，正对"隐私焦虑"痛点，差异化最锐利。
- **零依赖单文件分发**：双击即用，安装门槛极低，适合尝鲜与内容创作场景。
- **字幕 + 录屏烧录工作流**：竞品普遍缺失，是"陪伴 + 内容创作"复合定位的独门能力。
- **数字人视频反向代理**：在浏览器侧聚合腾讯智影 / HeyGen，规避 CORS 与密钥明文。
- **傲娇人设状态机离线可用**：断网也有"性格"，弱网/离线体验优于云端竞品。

### 3.2 劣势（Weaknesses）
- **单一固定角色**：竞品已 UGC / 多角色 / 群聊，小雅只有一个"小雅"。
- **记忆弱**：仅 `localStorage` 明文键值，无语义记忆、无跨会话抽象，关系感断档。
- **无真实大模型默认**：本地引擎关键词驱动，对话深度浅；接入大模型需用户自备 Key。
- **TTS 依赖系统语音包**：音色机械、情感缺失，是体验短板。
- **无移动端 / 无通话**：沉浸感与陪伴感落后于 X Eva、Replika。
- **无商业化、无合规基建**：身份验证、AI 标识、防沉迷、危机干预全部空白。

### 3.3 机会（Opportunities）
- 监管收紧下，"本地优先 + 可审计"成为稀缺卖点。
- 数字人 + 陪伴 + 内容创作三合一空白市场。
- 国内情感陪伴高增速（CAGR≈148%），长尾差异化产品有窗口。

### 3.4 威胁（Threats）
- 合规红线一票否决，停运案例频发。
- 头部赢者通吃（Top10% 吃 89% 收入），同质化必死。
- 大厂数字人平台迭代快，反向代理依赖第三方接口稳定性。

## 4. 优化目标

### 4.1 北极星指标
- **7 日留存 ≥35%**（行业基线 <20%），**单次会话时长 ≥12 分钟**，**离线可用率 100%**。
  - *目标推导（R3 修订）*：35% 非拍脑袋——取头部均值(≈20%)上浮约 1.7 倍，对应"长期记忆 + 关系进度"两项新增留存钩子的保守预期（参照 Nomi/Replika 靠记忆机制将 7 日留存推至 30%~40% 区间）。上线后需 A/B 验证，首版允许下调至 ≥28% 作为准入线。
- **合规零事故**：通过国内拟人化互动办法关键条款自检。

### 4.2 三大优化方向
1. **守住底线**：合规与安全前置，把"本地优先隐私"做成可对外承诺的产品特性（对外口径见 §1.4：本地优先 · 默认不上云 · 增强明示出境可关）。
2. **做深陪伴**：长期记忆 + 人设进化 + 语音情感化，把"关系感"做厚，直击留存。
3. **放大独特性**：强化"陪伴 + 内容创作"复合定位（字幕/录屏/数字人），形成竞品短时无法复制的护城河。

## 5. 优化需求规格（按优先级分级）

> 优先级定义：**P0** 合规/安全红线，不通过不可发布；**P1** 体验核心，首发必做；**P2** 增强；**P3** 探索。

### 5.1 P0　合规与安全（强制）

> **合规依据（2026-08 更新）**：本节所有合规项依据《人工智能拟人化互动服务管理暂行办法》（2026-04-10 公布、2026-07-15 施行、五部门令第21号）**正式稿**执行。此前文档中的"征求意见稿 / 正式稿待复核"表述均已失效。其中「不得向未成年人提供虚拟伴侣等虚拟亲密关系服务」为硬性要求，直接决定 REQ-COMP-02 的设计（见下）。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-COMP-01 | **AI 生成标识** | 首次进入与每次数字人/语音输出处显著标注"由 AI 生成，非真人"，且不可关闭（对齐《办法》标识义务） |
| REQ-COMP-02 | **年龄验证 / 实名 / 未成年拒服** | 首次启动强制年龄确认（自认 + 预留实名位）；**一旦识别为未成年人（<18），直接拒绝提供虚拟伴侣服务并给出合规说明与替代建议**（依据《办法》"不得向未成年人提供虚拟伴侣等虚拟亲密关系服务"硬要求）；保留可审计确认记录于本地。*2026-08 修订*：原"未成年模式功能收敛"方案已被正式《办法》取代——虚拟亲密关系服务对未成年人一律不可提供，不再做"收敛"设计（详见《修订_安全与一致性_P0.md》§5） |
| REQ-COMP-03 | **防沉迷提醒** | 连续使用 ≥2 小时弹窗/对话提醒休息（对齐《办法》）；未成年拒服由 REQ-COMP-02 统一处理，不再单独计时锁定 |
| REQ-COMP-04 | **情感危机识别与人工接管** | 关键词/情绪模型识别自伤、绝望等信号时，立即停止 AI 回复，弹屏提供心理援助热线与"转人工"入口，记录事件 |
| REQ-COMP-05 | **数据训练授权开关** | 默认"禁止用我的对话训练模型"且不可改为允许（本地优先原则）；明确隐私声明本地化呈现 |
| REQ-COMP-06 | **内容安全过滤** | 本地引擎与接入大模型响应均过敏感词/价值观过滤层；可配置但底线不可关闭 |
| REQ-COMP-07 | **本地数据可清除与可导出** | 一键清空全部本地数据（含记忆）；一键导出为标准格式，满足"可携带/可销毁" |
