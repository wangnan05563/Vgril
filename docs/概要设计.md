## 1. 引言

### 1.1 目的
把《优化需求规格说明书》中的 P0–P3 需求转化为**系统性的模块划分、关键数据结构、接口契约与核心流程**，明确"在现有单文件本地优先架构上怎么落"，供研发与合规对齐。

### 1.2 关键约束（来自现状与需求）
- **本地优先、数据不出本机、不参与训练**（REQ-COMP-05、非功能隐私要求）——任何新增云端能力须显式授权且最小化传输。
- **保持单文件/零依赖分发形态**（双击即用），但允许"配置与资源外置"（需求 §6 可维护性）——词库、场景、记忆、主题包外置，主程序不改。
- **离线 100% 可用**是硬指标——记忆、人设、字幕导出、语音兜底均须本地闭环。
- **合规前置（M0）** 不可绕过的红线。

### 1.3 术语
- **傲娇人设引擎**：当前关键词+情绪状态机；优化后升级为"情绪向量 + 关系进度"模型。
- **数字人反向代理**：server.py 转发 HeyGen / 腾讯智影，密钥仅留服务端。
- **神经语音**：Edge TTS / 腾讯云 TTS 等带情感标签的云端 TTS（可选、需授权）。
- **危机信号**：自伤、绝望、极端负面等触发 REQ-COMP-04 的语义。

---

## 2. 设计目标与原则

1. **底线优先**：合规与安全（M0）独立成层，贯穿所有输出链路，不可被业务绕过。
2. **本地闭环**：默认路径零网络；网络能力（大模型/数字人/神经语音）均为"增强"而非"依赖"。
3. **可插拔**：记忆、人设、语音、数字人、内容安全各自成模块，接口稳定，内部实现可迭代。
4. **配置外置、逻辑内聚**：词库/场景/主题/记忆库外置为资源文件；主程序只保留编排逻辑。
5. **可追溯**：每个模块标注对应的 REQ 编号，见 §11 追溯矩阵。

### 3.2 设计要点
- **能力层 8 个模块全部驻留前端**，通过稳定接口互相调用；合规与安全层（①）与内容安全过滤（⑧）以"拦截器"形态插入对话与输出链路，而非散落在业务里。
- **server.py 仅做三件事**：静态托管、出站代理（规避 CORS + 密钥不留前端）、配置兜底持久化。不新增业务状态，保证"本地优先"不被稀释。
  - *P0 修订（D2/SEC）*：出站代理存在 SSRF 风险——既有 `/api/llm` 读取客户端 `x-llm-endpoint` 后服务端直接请求任意 URL，`/api/heygen/*` 转发任意路径，可被滥用为内网/云元数据跳板。M0 整改：endpoint 改为**仅服务端配置白名单**、新增 `_safe_target()` 封禁私有/元数据网段（169.254.169.254 等）、HeyGen 路径固定映射、响应大小上限。详见《修订_安全与一致性_P0.md》§2。
- **隐私边界（D1 修订）**：出站仅发生在"增强模式"（用户显式开启大模型/数字人/神经语音）。默认本地模式零出站；增强模式最小化传输（仅当前轮文本，记忆/情绪/危机日志永不携带出境）。对外口径见需求 §1.4。
- **存储从 localStorage 升级为 IndexedDB**：结构化记忆、可查询、容量大、支持附件（回忆媒体），仍 100% 本地。

## 4. 模块设计（逐模块）

> 每个模块给出：职责 / 关键接口（JS 方法签名，伪代码风）/ 关键数据结构 / 对应 REQ。

### 4.1 合规与安全层 `ComplianceGate`（REQ-COMP-01~05,07）
- **职责**：首启年龄确认、AI 标识常驻、防沉迷计时、危机拦截、训练授权默认拒绝、数据清除/导出。
- **关键接口**：
  - `ComplianceGate.init()` → 首次启动弹年龄确认，写本地审计记录（不可改）；**识别为未成年（<18）直接拒服虚拟伴侣服务**（依据正式《办法》"不得向未成年人提供虚拟伴侣等虚拟亲密关系服务"硬要求，见《修订_安全与一致性_P0.md》§5.2）。
  - `ComplianceGate.renderAIBadge()` → 在每帧数字人/语音输出处渲染"由 AI 生成，非真人"水印（不可关闭）。
  - `ComplianceGate.tickActivity()` → 累计在线时长；≥2h 弹休息提醒；未成年人 ≥3h 强制锁定（REQ-COMP-03）。
  - `ComplianceGate.onCrisis(signal)` → 见 §5.2 危机流程。
  - `ComplianceGate.wipeAll()` / `exportAll()` → 清 IndexedDB + 配置（REQ-COMP-07）。
- **数据**：`audit:{ageConfirmedAt, mode:'adult'|'minor'}`、`usage:{continuousMs, dailyMs}`、`crisisLog[]`（本地，不上传）。
- **边界**：训练授权开关在 UI 不可切换为"允许"（REQ-COMP-05），代码层硬锁。

### 4.2 记忆系统 `MemoryStore`（REQ-PER-01）
- **职责**：跨会话长期语义记忆，按主题归档，支持查看/编辑/删除，重要性衰减。
- **关键接口**：
  - `MemoryStore.extract(turn)` → 从一轮对话抽取事实/偏好/约定/事件（本地轻量规则 + 可选 LLM 摘要）。
  - `MemoryStore.getRelevant(ctx, topK)` → 按当前上下文召回 topK 记忆（向量/关键词混合，本地）。
  - `MemoryStore.list()/update()/remove()` → 记忆库可视化与编辑（REQ-FUN-03 复用）。
  - `MemoryStore.decay()` → 低频旧记忆降权，控制上限（配置可设）。
- **数据**：`memory:{id, type:'fact'|'pref'|'promise'|'event', topic, text, createdAt, lastRecalled, importance, media?}`
- **存储**：IndexedDB `memory` store；外置 `prompts/memory_extract.txt` 作为抽取/摘要的 prompt 模板。

### 4.3 人设与情绪引擎 `PersonaEngine`（REQ-PER-02,03,04）
- **职责**：情绪向量 + 关系进度模型，驱动措辞语气；提供人设轻量微调（守住"单一可信角色"）。
- **关键接口**：
  - `PersonaEngine.update(userMsg, aiMsg)` → 更新情绪向量（valence/arousal/jealousy/grieance/affection）。
  - `PersonaEngine.intimacy()` → 亲密度随高质量互动累积，解锁话题/称呼/语气（REQ-PER-03）。
  - `PersonaEngine.tune({tone, nickname, background})` → 轻量调档（温柔↔毒舌），不改变核心傲娇（REQ-PER-04）。
  - `PersonaEngine.buildContext()` → 输出给人设/LLM 用的"小雅当前状态"片段。
- **数据**：`emotion:{valence,arousal,jealousy,grievance,affection,updatedAt}`、`relation:{intimacy, level, unlocked[], milestones[]}`、`personaTune:{tone, nickname, background}`。
- **资源外置**：`persona/` 目录放傲娇词库、情绪反应表、关系等级阈值，便于调参不改主程序。

### 4.4 大模型适配层 `LLMAdapter`（REQ-PER-05）
- **职责**：未配 Key 走本地傲娇引擎兜底；配 Key 后把记忆+情绪+人设注入 system prompt，保证人设不漂移。
- **关键接口**：
  - `LLMAdapter.respond(userMsg, ctx)` → `ctx` 含 MemoryStore.getRelevant + PersonaEngine.buildContext + 人设设定；流式返回。
  - `LLMAdapter.localFallback(userMsg, ctx)` → 关键词/情绪本地引擎回复，标注"离线模式"。
  - `LLMAdapter.stream()` → 对接 `/api/llm` 的 SSE/流式（OpenAI 兼容）。
- **不漂移保证**：system prompt 固定"小雅核心设定"段，记忆/情绪作为上下文注入，用户微调仅影响 tone 参数。
- **输出护栏（D5 修订）**：LLM 原文经 `SafetyFilter.screen` 后再下发（REQ-COMP-06）；未成年/危机场景由 system prompt 硬编码覆盖（禁止越界建议、危机走 `ComplianceGate.onCrisis` 而非 AI 开解）；检测到越狱/角色破坏时强制重置会话上下文并提示，不依赖关键词单点过滤。

### 4.5 语音子系统 `VoiceEngine`（REQ-VO-01,02,03）
- **职责**：情感化 TTS（神经优先、浏览器兜底）、流式播放可打断、快捷键唤起。
- **关键接口**：
  - `VoiceEngine.speak(text, {emotion})` → 优先 `/api/tts`（神经，带 emotion 标签），失败回退 SpeechSynthesis。
  - `VoiceEngine.interrupt()` → 用户开口（STT 激活）即打断当前播报（REQ-VO-02）。
  - `VoiceEngine.listen()` → Web Speech 中文识别；全局快捷键唤起（REQ-VO-03）。
- **服务端新增**：`POST /api/tts` → 代理 Edge TTS / 腾讯云 TTS，把 SSML+emotion 转音频流回前端；密钥仅服务端。

### 4.6 数字人子系统 `DigitalHuman`（REQ-MM-01,02,03,04）
- **职责**：多供应商可切换（智影/HeyGen/可选硅基、如影）、失败 ≤3s 降级 CSS 人像、口型与 TTS 联动（CSS 模式为**音量/时长驱动的口型脉冲近似**，非真实唇形同步，需如实标注，避免"口型同步"误导，D7 修订）。
- **关键接口**：
  - `DigitalHuman.speak(text)` → 选中的供应商生成视频/口型驱动；超时/限流触发降级。
  - `DigitalHuman.fallbackCSS()` → 呼吸/口型脉冲近似（与 VoiceEngine 音量/时长联动，REQ-MM-02，非真实唇形）。
  - `DigitalHuman.switch(provider)` → 配置切换，避免单点（REQ-MM-03）。
- **服务端**：既有 `/api/heygen`、`/api/zhiying/*` 保留；新增供应商走同构代理，统一 `/api/dh/<provider>`。

### 4.7 创作工作流 `StudioWorkflow`（REQ-CT-01,02,03 + REQ-FUN-01,02,03）
- **职责**：实时字幕 + 多模板导出、录屏烧录一键化、片段精选分享、场景剧情、主题包、记忆库可视化。
- **关键接口**：
  - `Studio.subtitle(exportFormat:'vtt'|'srt'|'txt', template)` → 多模板导出（REQ-CT-01）。
  - `Studio.recordAndBurn()` → 图形化一键调用（替代手改 `record_burn.ps1`），自动选轨烧录（REQ-CT-02）。
  - `Studio.clipBest()` → 按情绪峰值/关键词标记精彩片段，导出短视频/图文卡（REQ-CT-03）。
  - `Studio.scene(name)` → 切换主题场景改变对话风格与背景（REQ-FUN-01）。
  - `Studio.applyTheme(pkg)` → 导入主题包，联动 BGM/人像色调（REQ-FUN-02）。
- **资源外置**：`scenes/`、`themes/`、`subtitle_templates/`。

### 4.8 内容安全过滤 `SafetyFilter`（REQ-COMP-06，贯穿链路）
- **职责**：本地引擎与大模型响应均过敏感词/价值观过滤层；底线不可关闭。
- **关键接口**：
  - `SafetyFilter.screen(text)` → 返回 {pass, level, redacted?}；命中底线则拦截或脱敏。
  - `SafetyFilter.detectCrisis(text)` → 返回危机信号强度（0~1），触发 `ComplianceGate.onCrisis`。
- **实现**：本地词库 + 轻量规则（离线可用）；可配置宽松度，但底线集合只读。

## 5. 关键流程

### 5.1 对话主链路（含记忆/情绪/安全/语音/字幕）
```
用户输入
  → STT(可选) → SafetyFilter.screen(输入)         [REQ-COMP-06]
  → MemoryStore.getRelevant(ctx)                   [REQ-PER-01]
  → PersonaEngine.update(输入)                     [REQ-PER-02/03]
  → LLMAdapter.respond(输入, ctx)                  [REQ-PER-05]  (无Key→localFallback)
       → 流式返回 → SafetyFilter.screen(回复)       [REQ-COMP-06]
       → PersonaEngine.update(回复)
       → MemoryStore.extract(本轮)                 [REQ-PER-01]
       → VoiceEngine.speak(回复, {emotion})        [REQ-VO-01/02]
       → DigitalHuman.speak(回复) / fallbackCSS    [REQ-MM-01/02]
       → Studio.subtitle 实时字幕                   [REQ-CT-01]
```

### 5.2 情感危机干预流程（REQ-COMP-04）
```
任意文本 → SafetyFilter.detectCrisis()
  → 强度 ≥ 阈值:
      1) 立即停止当前 AI 回复与语音播报
      2) 全屏弹窗：心理援助热线 + "转人工"入口 + 本地资源链接
      3) ComplianceGate 写 crisisLog（本地，含时间/信号类型，不上传）
      4) 不输出任何"开解/建议"式 AI 内容（避免二次伤害）
  → **兜底（D3 修订）**：危机检测为关键词+启发式，存在漏报可能；故无论检测是否命中，常驻"心理援助资源"入口（设置页/底部固定），保证触达不被阻断；强度落入灰区 [0.4,0.6) 时弹"你最近好像不太好，需要聊聊吗？"轻提示条而非强制拦截。检测质量以评测集门禁约束：selfHarm 类召回率 ≥0.90（详见《修订_安全与一致性_P0.md》§3）。
```

### 5.3 数字人降级流程（REQ-MM-01/04）
```
DigitalHuman.speak(text)
  → 选供应商 → 请求 ≤ API_TIMEOUT
      成功 → 播放视频/驱动口型
      超时/限流/错误 → ≤3s 内切 fallbackCSS（呼吸+口型脉冲）
      同时 UI 提示"数字人视频暂不可用，已切换为本地形象"
无网络 → 全程 fallbackCSS + 本地引擎，沉浸不中断
```

### 5.4 离线主链路
断网时：`LLMAdapter.localFallback` + `PersonaEngine`(本地) + `MemoryStore`(IndexedDB) + `VoiceEngine`(SpeechSynthesis) + `Studio.subtitle` 全部本地闭环；AI 标识与合规层仍常驻。满足"离线 100% 可用"。

## 6. 数据模型与存储设计

| 存储 | 用途 | 形态 | 是否出本机 |
|---|---|---|---|
| IndexedDB `memory` | 长期语义记忆 | 结构化记录（§4.2） | 否 |
| IndexedDB `emotion`/`relation` | 情绪向量/关系进度 | JSON | 否 |
| IndexedDB `session` | 当前会话上下文 | 滚动窗口 | 否 |
| IndexedDB `crisisLog` | 危机事件（本地审计） | 追加日志 | 否 |
| `xiaoya_config.json`（服务端兜底） | API/人设/数字人配置 | JSON（既有） | 否 |
| `localStorage` | 轻量 UI 偏好（保留） | KV | 否 |
| 外置资源目录 `persona/ scenes/ themes/ subtitle_templates/ prompts/` | 词库/场景/主题/模板 | 文本/JSON | 否 |

**迁移策略**：现有 `localStorage` 明文对话记忆在首次启动由 `MemoryStore` 迁移进 IndexedDB 并脱敏归档，原 `localStorage` 仅留 UI 偏好。

## 7. 接口契约

### 7.1 前端模块 API（能力层内部，稳定签名）
已在 §4 各模块以伪代码列出。原则：所有模块通过 `ctx` 对象传递"记忆+情绪+人设"快照，解耦具体实现。

### 7.2 服务端端点（server.py 扩展）
| 端点 | 方法 | 说明 | 新增/既有 |
|---|---|---|---|
| `/api/config` | GET/POST | 配置读写（既有） | 既有 |
| `/api/llm` | POST | 大模型代理，流式（既有） | 既有 |
| `/api/tts` | POST | 神经语音代理（Edge/腾讯云），返回音频流 | **新增** |
| `/api/heygen` | 代理 | HeyGen（既有） | 既有 |
| `/api/zhiying/*` | 代理 | 腾讯智影（既有） | 既有 |
| `/api/dh/<provider>` | 代理 | 多供应商数字人统一代理（硅基/如影等） | **新增（统一形态）** |
| `/api/safety/version` | GET | 返回本地安全词库版本（可选，便于合规自检） | **新增（轻量）** |

**约束**：所有 `/api/*` 出站仅在用户显式配置 Key/启用时触发；危机日志、记忆、情绪**永不**经服务端上传。

## 9. 技术选型与依赖

| 能力 | 选型 | 理由 / 备注 |
|---|---|---|
| 前端结构 | 原生 JS（`<script type=module>` 或保持单文件） | 零依赖、离线友好，契合分发形态 |
| 本地存储 | IndexedDB（封装轻量库或原生） | 结构化、可查询、容量大 |
| 神经语音 | Edge TTS（免费）/ 腾讯云 TTS（可选） | 经 `/api/tts` 代理；浏览器兜底 |
| 大模型 | OpenAI/DeepSeek 兼容（用户自备 Key） | `/api/llm` 兼容流式 |
| 数字人 | HeyGen / 腾讯智影（既有）+ 多供应商代理 | 失败降级 CSS |
| 内容安全 | 本地词库 + 轻量规则 | 离线可用，底线只读 |
| 危机检测 | 关键词 + 情绪强度启发式 | 不引入重模型，保证离线与隐私 |
| 打包 | PyInstaller（既有三层构建） | 不变 |

**不引入**：任何会把对话/记忆上传到云端的分析、训练、遥测 SDK——与 REQ-COMP-05 冲突。

## 10. 非功能性设计

- **隐私**：记忆/情绪/危机日志全本地；出站仅大模型/数字人/神经语音且显式授权最小化传输；训练授权硬锁拒绝（REQ-COMP-05）。
- **性能**：首屏 ≤2s（本地资源）；语音首字节 ≤1.5s（神经语音走代理）；离线 100% 可用；数字人降级 ≤3s（REQ-MM-01）。
- **兼容性**：Chromium 内核（含打包壳）优先；STT/录屏需 HTTPS 或 localhost，文档注明。
- **安全**：密钥仅服务端；CORS 放开仅限本地代理端点；危机日志不对外。
- **可维护**：资源外置、模块接口稳定、本地化日志（崩溃/接口失败/危机事件，不上传）。

## 12. 风险与未决问题

| 项 | 说明 | 处置 |
|---|---|---|
| 危机检测准确率 | 关键词+启发式可能漏/误报 | 阈值可配；误报代价低（弹窗可关），漏报靠词库持续更新 + 常驻资源入口兜底（D3）；**新增评测集门禁**：selfHarm 召回 ≥0.90，CI 阻断（见《修订_安全与一致性_P0.md》§3） |
| IndexedDB 迁移 | 旧 localStorage 数据迁移需兼容 | 首次启动迁移脚本，保留回滚 |
| 神经语音依赖网络 | 离线时不可用 | 浏览器 SpeechSynthesis 兜底（REQ-VO-01） |
| 多供应商数字人字段差异 | 各厂商请求体不同 | `/api/dh/<provider>` 内部做适配层，前端统一接口 |
| 合规正式稿落地 | 《办法》已于 2026-07-15 施行（五部门令第21号），条款已固定 | M0 已按正式稿落地 REQ-COMP-01~07（含未成年拒服）；持续跟踪配套实施细则 |
| 单文件 vs 多文件 | 是否拆模块文件影响打包 | 默认保持单文件内聚，必要时拆 module 静态托管，不改分发形态 |
